# lst-signbox-lists-tgbot

Лёгкий Telegram-бот для OpenWrt 24.10 (opkg) и 25.12 (apk): управление файлами списков доменов и IP через inline-кнопки. Работает с [podkop](https://github.com/itdoginfo/podkop) и [forkop](https://github.com/ushan0v/forkop) — какой из них установлен, бот определяет сам.

## Возможности

- Приём списка доменов или IP/CIDR (через запятую, пробел или с новой строки)
- Импорт прокси-ссылок файлом подписки или списком в сообщении: отбор по ⚡ (снимается кнопкой), отсев LTE, замер задержки и запись в секцию podkop/forkop
- Автоопределение типа (домен / IP)
- Действия: добавить, удалить, отключить (`// value`), отмена
- Умная обработка уже существующих и отключённых записей
- Категории: раскладка записей по группам, просмотр и отключение/удаление группой
- Работа по секциям podkop/forkop: бот читает `/etc/config/podkop` или `/etc/config/forkop` и показывает списки той секции, которую вы выбрали
- Привязка нового файла списка к секции прямо из чата (`uci add_list` + создание файла)
- Проверка файлов при `/start`, создание при отсутствии
- Предупреждение о несинхронизированном перезапуске сервиса + кнопка перезапуска
- Уведомление в чат о выходе новой версии
- Обновление бота кнопкой прямо из чата («Настройки» → «Обновить бота»)
- Настройка через LuCI: токен бота и пути к файлам



## Быстрый старт



### 1. Создайте бота в Telegram

1. Откройте [@BotFather](https://t.me/BotFather)
2. `/newbot` → задайте имя и username
3. Скопируйте токен

> Бот привязывается к первому написавшему (см. [«Доступ к боту»](#доступ-к-боту)), но всё равно не публикуйте username — до первого `/start` бот открыт для того, кто напишет первым.



### 2. Установка на OpenWrt

**Автоматически:**

```bash
wget -qO- https://raw.githubusercontent.com/bpGusar/signbox-custom-lists-tgbot/main/install.sh | sh
```

`install.sh` сам выбирает формат: на OpenWrt 25.12+ (apk) ставит `.apk`, на 24.10 (opkg) — `.ipk`.
Пакеты берутся из GitHub Release (приоритет), иначе из `dist/apk/` или `dist/ipk/` в репозитории.

**Сборка** (Docker, `Dockerfile-ipk` + OpenWrt SDK; формат задаёт версия SDK):

```bash
make ipk                    # .ipk для 24.10, все архитектуры
make apk                    # .apk для 25.12, все архитектуры
make packages               # оба формата
make ipk-aarch64            # только aarch64 (есть и apk-aarch64)
TARGETS=mipsel_24kc make ipk
```

Пакеты: `dist/ipk/<архитектура>/` и `dist/apk/<архитектура>/`. Внутри `.apk`
архитектура в имени не указывается, поэтому сборка переименовывает их так же,
как `.ipk`: `lst-signbox-lists-tgbot_<версия>_<архитектура>.apk`.

Версия назначается автоматически: `0.YYYYMMDD.<номер_сборки>` (например `0.20260611.42`).  
При каждом push в `main` GitHub Actions собирает оба формата, создаёт Release и обновляет `dist/`.



Ручной запуск: **Actions → Build packages → Run workflow**.

### 3. Настройка в LuCI

**Services → Lists Telegram Bot**

- **Enabled** — включить бота
- **Bot Token** — токен от BotFather

Сохранить и применить.

### 4. Telegram

Отправьте боту `/start`, затем список:

```
test.com, example.org
```

или

```
1.1.1.1, 10.0.0.0/8
```



## Доступ к боту

У бота нет ролей/белого списка — управлять списками и перезапуском может любой, кто сможет ему написать. Чтобы это не превращалось в «кто первый нашёл username, тот и рулит маршрутизацией», бот **привязывается к первому чату**, который отправит ему любое сообщение:

- Первый `/start` (или любое другое сообщение) после установки/обновления сохраняет `chat_id` отправителя как владельца в `state.json` (`owner_chat_id`).
- Все остальные чаты получают отказ («🔒 Этот бот уже привязан к другому пользователю») и не могут ни читать, ни менять списки.
- При обновлении с версии без этой проверки владельцем станет тот, кто напишет боту первым **после** обновления — если это важно, напишите боту сразу после установки пакета/перезапуска сервиса.

**Сброс привязки** (например, чтобы передать бота другому человеку или переустановить): остановите бота, удалите поле `owner_chat_id` из файла состояния (по умолчанию `/var/lib/lst-signbox-lists-tgbot/state.json`, путь настраивается через `state_path`) или файл целиком, затем запустите бота снова — следующий написавший станет новым владельцем.

## Формат файлов

```
// #cat: YouTube
googlevideo.com
ytimg.com
// #cat: Реклама
ads.example.com
// tracker.example.com
// #uncat
test.com
example.org
// disabled.com
```

- Отключённая запись: `//` + пробел + значение.
- Заголовок категории: `// #cat: ` + имя. Всё до следующего заголовка относится к этой категории.
- `// #uncat` открывает блок «Без категории» — он всегда идёт последним, после всех именованных категорий.

Обе директивы — обычные `//`-комментарии, поэтому podkop/sing-box их игнорирует так же,
как и отключённые записи. Файлы без директив читаются как раньше: всё попадает
в «Без категории», и бот ничего в них не дописывает.

Домены сортируются внутри своей категории (по регистрируемому домену), IP сохраняют
порядок добавления. Любые другие `// #...` строки бот считает комментарием-разделителем
и при перезаписи файла не сохраняет.

## Категории

Категория — способ держать пачку доменов вместе, чтобы её можно было целиком
отключить или удалить, не выискивая записи по всему файлу.

**Добавление.** Отправьте список как обычно. Кроме `➕ Добавить` (кладёт записи
в «Без категории») есть `📂 Добавить в категорию` — бот покажет категории
кнопками:

```
📂 В какую категорию добавить 20 записей?

Выберите категорию кнопкой ниже или создайте новую.

[ YouTube · 12✅ 3⏸ ] [ Реклама · 40✅ ]
[ Без категории · 7✅ ]
[ 🆕 Новая категория ]
[ ❌ Отмена ]
```

Короткие имена бот кладёт по 2–3 в строку, длинное занимает строку целиком —
так на экран помещается больше категорий.

`🆕 Новая категория` попросит прислать имя новой категории сообщением
(до 40 символов). Если категорий ещё нет, бот так и скажет — останется только
создать первую.

Если категорий больше 48, клавиатура получилась бы выше экрана, поэтому бот
показывает их списком команд прямо в тексте:

```
/gd_7f3a2b19_a1b2c3d4 — YouTube — 12 ✅ / 3 ⏸
/gd_7f3a2b19_5e6f7a8b — Реклама — 40 ✅
/gd_7f3a2b19_none — Без категории — 7 ✅
```

Тап по команде сразу отправляет выбор боту, своё сообщение с командой бот
удаляет, чтобы чат не засорялся. В команде две части: `7f3a2b19` — id операции
(какой именно список добавляем), `a1b2c3d4` — id категории. Нажатие приходит
боту просто текстом, без привязки к сообщению, поэтому id операции едет прямо
в команде: тап в старом сообщении применится к его списку, а не к последнему
отправленному. Id категории — хеш её имени, так что ссылки в старых сообщениях
не протухают.

Если часть записей уже лежит в другой категории, бот об этом скажет и предложит
кнопку `📦 Переместить`.

**Список сразу с категориями.** Можно прислать записи в том же виде, в каком
они лежат в файле, — с заголовками `// #cat: имя`:

```
// #cat: xda
xda-developers.com
xdaforums.com
// #cat: cursor
cursor-cdn.com
cursor.com
cursor.sh
```

Бот поймёт по записям, домены это или IP, спросит секцию и покажет, сколько
записей в какую категорию попадёт. `➕ Добавить` кладёт новые записи
в их категории; записи до первого заголовка или после `// #uncat` попадают
в «Без категории». Записи, которые уже есть в файле, остаются в своей категории.
`📂 Добавить в категорию` всё равно кладёт весь список в одну выбранную категорию.

**Просмотр.** `📋 Показать домены` / `📋 Показать IP` в карточке секции
открывают выбор:

- `📄 Показать все` — все категории одним сообщением, содержимое каждой убрано
  в разворачиваемую цитату. Если не влезает в лимит Telegram, бот разобьёт вывод
  на несколько сообщений по границам категорий, а слишком большую категорию
  отправит файлом.
- `📂 Показать категорию` — кнопка на каждую категорию (или тот же список команд,
  если категорий больше 48), тап открывает карточку категории прямо в этом же
  сообщении. Кнопка `📂 Категории` в карточке возвращает к списку, так что
  переходы туда-сюда не плодят новых сообщений в чате.

**Карточка категории** даёт действия над всей группой: `⏸ Отключить все`,
`✅ Включить все`, `📦 Переместить записи` (в другую категорию), `✏️ Переименовать`,
`🗑 Удалить категорию` (записи переезжают в «Без категории» и продолжают работать)
и `🗑 Удалить с записями` (удаляет всё, с подтверждением).

Категории у доменов и IP независимы: это разные файлы, и одноимённые категории
в них не связаны. Пустая категория в файле не хранится — она исчезает вместе
с последней записью.

## Podkop и forkop

Бот работает с тем, что установлено на роутере, и определяет это по
init-скрипту: `/etc/init.d/podkop` или `/etc/init.d/forkop`. Ничего настраивать
не нужно — название (`podkop`/`forkop`) бот подставляет в кнопки и сообщения.

Если установлены **оба**, бот на любое сообщение отвечает ошибкой и ничего не
делает: их конфиги по-разному описывают одни и те же списки. Удалите лишний
пакет — бот продолжит работу без перезапуска.

Бот поддерживает forkop 2.0 и новее (конфиг `config_version '2.0.0'`, ядро
`sing-box-forkop`). Отличия forkop, которые учитывает бот:

| | podkop | forkop |
|---|---|---|
| Конфиг | `/etc/config/podkop` | `/etc/config/forkop` |
| Тип секции | `connection_type` | `action` (`connection`, `block`, …) |
| Файлы списков | `local_domain_lists` и `local_subnet_lists` | наборы правил: `rule_set` (домены) и `rule_set_with_subnets` (домены и IP) |
| Ссылки прокси | `urltest_proxy_links` / `selector_proxy_links` | дочерние секции `connection_link` у секций `action=connection` |
| Замер через туннель | `sing_box_config_facade.sh` | outbound `parser` ядра `sing-box-forkop` |
| Задержки после записи | `podkop clash_api get_group_latency <секция>` | `forkop clash_api GET /group/<имя секции>/delay` |

**Списки в forkop.** Файлы списков в forkop — наборы правил: из `rule_set`
берутся только домены, из `rule_set_with_subnets` — ещё и IP/CIDR. Строки `//`
и `#` (отключённые записи и категории бота) пропускаются. Бот привязывает
список доменов в `rule_set`, список IP — в `rule_set_with_subnets` (к
DNS-секции — только домены). Файл из `rule_set_with_subnets` бот считает
списком IP, если в нём только IP/CIDR, иначе — списком доменов; пустой файл —
по имени: `ip`, `subnet` или `cidr` в имени (`main_ip_list.lst`) значит список
IP. Поэтому имя файла со списком IP должно это содержать; предложенные ботом
пути этому уже соответствуют.

Ядро forkop не запускается, если файл списка отсутствует или в нём нет ни
одной записи (только комментарии и отключённые записи тоже не считаются).
Поэтому перед перезапуском бот проверяет файлы списков включённых секций и
при пустом файле не перезапускает forkop, а называет такие файлы.

## Секции

Podkop и forkop раскладывают маршрутизацию по секциям (`config section 'main'`,
`'youtube'`, `'Exclude'` и т.д.), и у каждой секции свои файлы списков
(в podkop — опции `local_domain_lists` и `local_subnet_lists`, в forkop —
`rule_set` и `rule_set_with_subnets`). Поэтому бот не работает
с «файлом доменов вообще»: сначала выбирается секция, потом действие.

```
🗂 Управление записями
   ↓
[ main · proxy · домены+IP ]
[ Exclude · exclusion · нет списков ]
[ youtube · proxy · домены ]
   ↓ (выбрали main)
🗂 main · proxy
📄 Домены: /etc/lst-signbox-lists-tgbot/domain_list.lst
📄 IP: /etc/lst-signbox-lists-tgbot/ip_list.lst

[ 📋 Показать домены ] [ 📥 Скачать домены ]
[ 📋 Показать IP ]     [ 📥 Скачать IP ]
```

Дальше работает обычная логика: просмотр по категориям, карточка категории,
выгрузка файла.

`local_domain_lists` и `local_subnet_lists` — UCI-списки, в секции может быть
несколько файлов. Тогда между действием и результатом бот спросит, какой из
них открыть. Если один и тот же файл привязан к нескольким секциям, бот
скажет об этом при добавлении записей — правка затронет их все.

**Куда добавлять записи.** Отправленный текстом список ни к какой секции не
привязан, поэтому бот спрашивает, в какую секцию его положить, и только потом
показывает `➕ Добавить` / `⏸ Отключить` / `🗑 Удалить`:

```
📥 домены — 2 записи

В какую секцию добавить?

[ 🗂 main ]
[ 🔗 Exclude · нет файла ]
[ 🗂 youtube ]
[ ❌ Отмена ]
```

Секции без файла для этого списка тоже в списке: выбор такой секции ведёт
к привязке файла, а после неё бот возвращается к тем же записям — пересылать
список заново не нужно. Целевой файл всегда написан в шапке сообщения
с действиями.

**Привязка файла.** Если у секции нет `local_domain_lists` (или
`local_subnet_lists`), в её карточке будет `🔗 Привязать файл`. Бот предложит
путь вида `/etc/lst-signbox-lists-tgbot/<секция>_domain_list.lst`, свой путь
можно прислать сообщением. По подтверждению бот выполняет
`uci add_list podkop.<секция>.local_domain_lists=<путь>` + `uci commit podkop`
(в forkop — `uci add_list forkop.<секция>.rule_set=<путь>` или
`rule_set_with_subnets` для IP + `uci commit forkop`), создаёт файл и
напоминает, что сервис нужно перезапустить.

Путь принимается только абсолютный, без `..`, из латиницы, цифр и `. _ - /` —
он попадает в чужой конфиг и в него же бот потом пишет.

**Если не установлен ни podkop, ни forkop**, бот на любое действие отвечает
ошибкой и не работает, пока не будет установлен один из них.

`⚙️ Настройки` → `🔗 Проверить Podkop` (или `Forkop`) показывает все секции и привязанные
к ним файлы одним сообщением.

## Импорт прокси-ссылок

Откройте `🔗 Управление ссылками прокси` в главном меню — бот расскажет, каким
должен быть список, и начнёт ждать его. Дальше есть два способа его прислать:

- отправить `.txt` со ссылками (обычный файл подписки);
- вставить ссылки прямо в чат сообщением, по одной в строке.

Бот отберёт из списка быстрые узлы и запишет их в секцию podkop/forkop. Файл или
список, присланный без этого шага, бот не принимает — вместо разбора он покажет
ту же инструкцию. Пока экран загрузки открыт, сообщение со ссылками (любая
строка со схемой `xxx://`) уходит в этот разбор, а не в списки доменов.

```
📥 Прокси-ссылки · subscription.txt

Строк: 278
Ссылок: 278
С ⚡: 83
Без ⚡: 195
Отсеяно по LTE: 64
Схлопнуто дублей: 5

К проверке: 30 — 25 уникальных адресов

⚡ Фильтр включён — берутся только ссылки с ⚡ в названии.

[ ⚡ Проверить с порогом 400 мс ]
[ ✏️ Ввести порог ]
[ 🔓 Проверить все ссылки, без ⚡ (194) ]
[ ❌ Отмена ]
```

**Что отбирается.** По умолчанию берутся только строки, помеченные ⚡ в подписи
(⚡️ с селектором варианта и голая ⚡ считаются одинаково). Кнопка
`🔓 Проверить все ссылки, без ⚡` снимает это условие: в проверку идут все
ссылки поддерживаемых схем, помеченные и нет. Кнопка есть и в обратную сторону
(`⚡ Вернуть фильтр ⚡`); переключение сбрасывает уже снятые замеры, потому что
это другой набор ссылок. Если ⚡ нет ни на одной строке, бот не отказывает, а
сразу предлагает эту кнопку.

Отсев по `LTE` и схлопывание дублей работают в обоих режимах: выбрасываются
строки, где в подписи встречается слово `LTE`, а ссылки, отличающиеся только
подписью, схлопываются в одну — служебные разделители подписки («⬇️ Быстрые
⬇️», «⚠️ Если другие не работают ⚠️») обычно повторяют одну и ту же ссылку.
Один и тот же `host:port` с разными uuid — это разные учётки, они остаются
обе.

Проверка ссылки на безопасность для конфига podkop (пробелы, кавычки,
управляющие символы, длина, схема) не отключается ничем — она стоит на записи
в UCI, и её кнопка `🔓` не обходит.

Схемы — те, что принимает podkop: `vless`, `ss`, `trojan`,
`socks4/4a/5`, `hysteria2`, `hy2`; forkop принимает их все. Строки с другими схемами и всё, что не
разбирается как ссылка, попадают в счётчик «пропущено».

**Чем меряется пинг.** В два этапа:

1. TCP-хендшейк до `host:port` — 3 попытки, берётся лучшая, не больше
   4 адресов одновременно. Для `hysteria2`/`hy2` TCP-хендшейка нет, поэтому
   используется `ping` (ICMP).
2. Для тех, кто прошёл первый этап, — реальная задержка **через туннель**:
   бот просит конвертер podkop
   (`/usr/lib/podkop/sing_box_config_facade.sh`) собрать outbound'ы, а для
   forkop отдаёт каждую ссылку outbound'у `parser` ядра `sing-box-forkop` —
   так же, как делает сам forkop. Затем поднимает временный `sing-box` с
   Clash API на локальном порту и опрашивает `/proxies/<тег>/delay` по одному
   прокси за раз.

Второй этап нужен только там, где есть podkop или forkop, `sing-box` не старше,
чем им нужно (≥ 1.12.4 для podkop, `sing-box-forkop` ≥ 1.14.4 для forkop), и хватает свободной
памяти. Если чего-то из этого нет, бот молча остаётся на результатах
первого этапа и пишет в отчёте, чем именно померил.

Временный конфиг с живыми ключами лежит в `/tmp` с правами `0600` и удаляется
сразу после проверки; в чат и в логи ключи не попадают — в отчёте всегда
`vless://***@host:port`.

⚠️ И TCP-пробы, и временный `sing-box` ходят **с самого роутера**. Если IP
прокси-сервера попал в маршрутизируемый через podkop список, замер пойдёт
через туннель второй раз и цифра будет врать.

**Куда записывается.** В forkop — любая секция с `action=connection`, каждая
ссылка становится дочерней секцией `connection_link` (`section`, `uri`,
`name`, `order`). Имя бот берёт из подписи ссылки (`/` заменяется на `／`) или
ставит `Node`; занятое в секции имя получает ` #N`, как на странице forkop. В podkop бот предлагает секции, которые
принимают список ссылок — то есть `connection_type=proxy` с
`proxy_config_type` = `urltest` или `selector` (опции `urltest_proxy_links` /
`selector_proxy_links`). Секция типа `outbound` не показывается вовсе, а
секция типа `url` (одна ссылка в `proxy_string`) показывается отдельной
строкой: чтобы принять список, её надо переключить на URLTest. Бот сделает это
по явному подтверждению и перенесёт текущую ссылку первой в список.

Дальше — предпросмотр и выбор: `➕ Добавить` (`uci add_list`, в forkop —
`uci add` + `uci set`, только по тем, которых ещё нет) или `♻️ Перезаписать`
(`uci delete` списка или ссылок секции и запись заново).
В обоих случаях в конце один `uci commit podkop` (или `forkop`), после чего
сервис нужно перезапустить — как и при изменении списков.

**Про `%20` в подписях.** podkop разворачивает список ссылок в шелле без
кавычек (`for link in $urltest_proxy_links`), поэтому пробел внутри ссылки
разорвал бы её на несколько «ссылок» и генерация конфига упала бы. Перед
записью бот percent-кодирует во фрагменте после `#` все пробелы, кавычки,
обратные слэши и управляющие символы. LuCI показывает подпись через
`decodeURIComponent`, так что на экране `%20` снова выглядит пробелом. Эмодзи
остаются как есть.

После записи и перезапуска кнопка `📡 Задержки в podkop` (`в forkop`)
показывает, что получилось живьём — это уже замер самого сервиса
(`podkop clash_api get_group_latency` / `forkop clash_api GET /group/…/delay`).

**Лимиты:** файл до 1 МБ, до 5000 строк, до 300 ссылок после фильтров, до 30
ссылок в одной пачке проверки через туннель, общий дедлайн операции — 10 минут.
Проверку можно остановить кнопкой `⏹ Остановить`.

## Перезапуск сервиса

Команды перезапуска — список `restart_cmd` в `/etc/config/lst-signbox-lists-tgbot`
(в LuCI — поле «Restart commands», куда можно добавить сколько угодно строк).
Они выполняются по очереди через `sh -c`; первая упавшая команда останавливает
остальные. По умолчанию одна команда перезапускает тот из podkop и forkop,
что установлен:

```
list restart_cmd '/etc/init.d/$([ -x /etc/init.d/forkop ] && echo forkop || echo podkop) restart'
list restart_cmd '/etc/init.d/your-service restart'
```

После изменения списков бот покажет предупреждение и кнопку перезапуска.
Без команд в списке кнопки перезапуска нет. При обновлении старое значение
по умолчанию `/etc/init.d/podkop restart` заменяется новым, опция
`service_label` удаляется.

## Обновление из чата

Раз в 6 часов бот проверяет GitHub Releases и присылает владельцу сообщение,
когда выходит новая версия (о каждой версии — один раз). К уведомлению
прикреплена кнопка «Обновить бота» — обновиться можно прямо из него.

Тот же путь есть в меню: «Настройки» → «Обновить бота». Бот покажет
установленную и доступную версии, а по подтверждению запустит
`lst-signbox-lists-tgbot-upgrade start` в фоне.

Установка заканчивается перезапуском самого бота, поэтому он запоминает
операцию в `state.json` и дописывает результат в то же сообщение уже после
перезапуска. Во время установки бот недоступен около минуты.

Кнопка появляется, только если в системе есть
`/usr/sbin/lst-signbox-lists-tgbot-upgrade`. Обновление доступно владельцу
бота — тому чату, который привязан в `state.json`.

## Логи операций

По умолчанию бот пишет журнал действий в файл:

```bash
/etc/lst-signbox-lists-tgbot/logs/bot.log
```

Путь можно изменить через UCI:

```bash
uci set lst-signbox-lists-tgbot.main.log_path='/etc/lst-signbox-lists-tgbot/logs/bot.log'
uci commit lst-signbox-lists-tgbot
/etc/init.d/lst-signbox-lists-tgbot restart
```

Полезные команды на роутере:

```bash
# Последние 100 строк
tail -n 100 /etc/lst-signbox-lists-tgbot/logs/bot.log

# Смотреть в реальном времени
tail -f /etc/lst-signbox-lists-tgbot/logs/bot.log
```

Примеры событий: `/start`, разбор входного списка, нажатия кнопок, добавление/удаление/отключение записей, скачивание файлов, запуск и результат перезапуска сервиса, ошибки.

## Локальная разработка

Бот можно запускать на ПК без OpenWrt: конфигурация берётся из переменных окружения (UCI не нужен).  
Списки и логи по умолчанию пишутся в папку `testdata/` в корне репозитория.

**Требования:** Go 1.22+, токен тестового бота от [@BotFather](https://t.me/BotFather).  
Для разработки лучше отдельный бот — не запускайте локально бота с тем же токеном, что на роутере.

### Windows

Скрипт проверяет окружение, создаёт `testdata/`, настраивает переменные и предлагает запустить бота:

```powershell
.\scripts\dev-windows.ps1
```

Токен можно сохранить в `.env.local` (файл в `.gitignore`). При повторном запуске скрипт подхватит его автоматически.

После запуска скрипт следит за `*.go`, `go.mod` и `go.sum`: при изменении он сам пересобирает бинарник
и перезапускает бота. Если сборка падает, ошибка компилятора печатается в окно, а бот запустится
после первой удачной пересборки. Чтобы отключить слежение и просто запустить бота один раз:

```powershell
.\scripts\dev-windows.ps1 -NoWatch
```

### Linux / macOS

```bash
export LST_SIGNBOX_LISTS_TGBOT_TOKEN="your-token"
export LST_SIGNBOX_LISTS_TGBOT_RESTART_CMD="echo restart"
export LST_SIGNBOX_LISTS_TGBOT_STATE_PATH="/tmp/lst-signbox-lists-tgbot-state.json"
export LST_SIGNBOX_LISTS_TGBOT_LOG_PATH="/tmp/lst-signbox-lists-tgbot.log"

make build
./lst-signbox-lists-tgbot
```



### Тестирование

В Telegram: `/start`, затем список доменов или IP. Логи — `testdata/bot.log` (Windows) или путь из `LST_SIGNBOX_LISTS_TGBOT_LOG_PATH`.

Unit-тесты без Telegram:

```bash
go test ./...
```



### После изменений в коде

Запущенный бинарник не подхватывает правки сам — нужно пересобрать и перезапустить:

```bash
go build -trimpath -o lst-signbox-lists-tgbot ./cmd/lst-signbox-lists-tgbot   # Linux/macOS
go build -trimpath -o lst-signbox-lists-tgbot.exe .\cmd\lst-signbox-lists-tgbot  # Windows
```

Остановка работающего бота: `Ctrl+C`. На Windows `.\scripts\dev-windows.ps1` делает это сам:
он пересобирает и перезапускает бота при каждом изменении исходников (отключается флагом `-NoWatch`).
